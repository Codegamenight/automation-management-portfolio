# Root Cause Analysis

## Methodology
Root causes were identified using trend analysis, Pareto breakdowns, and incident postmortem reviews.

## Root Cause 1: Lack of Asset Criticality Classification
- All assets treated equally in maintenance planning
- No prioritization based on impact to throughput

## Root Cause 2: Reactive Incident Handling
- Focus on restoring operation quickly
- Limited follow-up on systemic fixes

## Root Cause 3: Inconsistent Work Standards
- Variability in troubleshooting approaches
- Limited standard operating procedures for common failures

## Root Cause 4: Data Fragmentation
- Performance data spread across systems
- Limited correlation between maintenance, alarms, and throughput
